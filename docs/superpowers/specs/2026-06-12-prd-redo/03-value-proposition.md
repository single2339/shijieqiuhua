# 世界球花 — 价值主张画布

## 0. 决策上下文

本文档要回答一个具体决策：

> **"懂球但不擅长读数据的足球迷，为什么会用世界球花，而不是已有的 [赛果预测站 / 论坛 / 数据站 / 大模型对话]？"**

如果不能给出 ≥ 2 个不可替代的答案，则 PRD v1 应该回到第 1 阶段重新框定，而不是继续往下做需求清单。

## 1. 前置假设（写在分析之前）

| ID | 假设 | 强度 | 验证方式 |
|---|---|---|---|
| VPA-A1 | 目标用户是 U1（懂球研判型，5+ 年球龄）；不是 U2（大赛偶尔看）也不是 U3（投注用户） | 中 `[A]` | 5-8 人定向访谈 |
| VPA-A2 | 用户**已经在用** ChatGPT/Claude/DeepSeek 提问比赛，且不满意 | 高 `[A]` | 访谈中直接问"你最近一次用 AI 问比赛是什么时候、效果如何" |
| VPA-A3 | 用户愿意为"证据链可追溯"付费，月度 < ¥30 | 低 `[A]` | 上线后定价 A/B 测试；初期可以付费码不定价 |
| VPA-A4 | 用户接受"研判 ≠ 胜负预测"的产品定义 | 中 `[A]` | 访谈中给出"信息不足"案例，看反应 |
| VPA-A5 | "足球研判"是一个有市场的细分品类，而不是足球分析市场被赔率/盘口完全占据 | 中 `[A]` | 调研：球探/捷报/SofaScore 是否覆盖此需求 |

**强度低的假设要在阶段 2 用户访谈中优先验证，否则 PRD v1 的全部价值主张都是空中楼阁。**

## 2. Customer 侧（用户视角）

### 2.1 Customer Jobs（用户要完成的任务）

| Job 类型 | Job | 频率 | 重要度 |
|---|---|---|---|
| **功能性 J1** | 在赛前 30 分钟内决定"这场我看好谁"以便看球时有个判断锚点 | 每比赛日 | 高 |
| **功能性 J2** | 验证自己心里的判断是否符合数据（Bayes update） | 比赛前 | 高 |
| **功能性 J3** | 看完默认主判断后，针对自己关心的具体维度（角球、红黄牌、半场）继续思考 | 每比赛 | 中 |
| **功能性 J4** | 赛后回看"我赛前的判断对不对"以提升自己的研判能力 | 赛后 | 中 |
| **情感性 J5** | 在朋友/球友面前显得"懂球" | 社交场景 | 中 |
| **情感性 J6** | 享受研判过程，把看球从"被动消遣"升级为"参与" | 看球时 | 高 |
| **社会性 J7** | 把分析结果分享给朋友或群里，触发讨论 | 偶尔 | 低 |

### 2.2 Customer Pains（痛点）

| ID | Pain | 严重度 | 频率 | 当前如何对付 |
|---|---|---|---|---|
| P1 | 赛果预测站只给"主队 1.85 倒数"这种盘口数字，看不到"为什么" | 高 | 每次 | 自己脑补 / 看大段分析文章（耗时） |
| P2 | 大模型（ChatGPT/DeepSeek）能对话但**信息过期、来源不明**，给的"分析"经常张冠李戴 | 高 | 每次 | 多问几个 LLM 交叉验证（仍不可靠） |
| P3 | 论坛/球评的分析文章**冗长、广告多、立场偏向**，难快速取用 | 中 | 每次 | 跳过 |
| P4 | 数据站（FBref/Transfermarkt/SofaScore）数据多但**不结论化**，要自己组装 | 中 | 高频用户 | 自己 Excel 整理（少数人坚持） |
| P5 | 我心里有疑问（"主队主场状态是不是被高估"）但**没有可问的对象** | 中 | 偶发 | 朋友讨论 / 闷在心里 |
| P6 | 移动端体验差，看球时不方便快速查证 | 中 | 临场 | 切换 App 烦 |
| P7 | 投注类产品的语言"诱导式"，让人不舒服或带来道德压力 | 中 | 偶发 | 回避 |
| P8 | 数据多到无法判断"哪个证据最关键"，决策疲劳 | 中 | 每次 | 凭直觉 |

### 2.3 Customer Gains（期望收益）

| ID | Gain | 类型 |
|---|---|---|
| G1 | 1 分钟内拿到带 3-5 条关键证据的研判 | 必需 |
| G2 | 每条结论能点开看到"凭什么这么说" | 必需 |
| G3 | 能就某个维度（红黄牌、角球）继续问 | 必需 |
| G4 | 看到"信息不足"时直接告诉我，而不是编一个倾向 | 必需 |
| G5 | 看球时手机上能用，不卡、不要登录三次 | 期望 |
| G6 | 历史问答能回看，赛后可以对照 | 期望 |
| G7 | 邀请朋友进来共同讨论 | 期望 |
| G8 | 文案专业但不冷冰冰，有"绿茵纸感" | 惊喜 |
| G9 | 不用绕开"投注语言"的尴尬 | 惊喜 |

## 4. Fit 评估（产品-市场匹配度）

| 维度 | 评分（1-5） | 说明 |
|---|---|---|
| Problem-Solution Fit | 4 | 解决 P1/P2/P5/P7 这种主流产品确实没解决的痛点 |
| Job 覆盖度 | 4 | J1-J4 直接覆盖；J5-J7 部分覆盖（社交需要 v1.5） |
| 紧迫度 | 3 | 不是刚需（球迷不研判也能看球）；但有较大研判型用户群 `[A]` |
| 替代品威胁 | 3 | LLM 通用对话是最大替代；只要本产品的"证据可追溯"+"无投注语言"持续做好，可形成壁垒 |
| 网络效应 | 2 | 邀请机制有微弱网络效应，但单用户价值不依赖他人，效应不强 |

## 5. 不可替代的差异化（USP）

按"如果对手做了同样的事，我们还剩下什么"逻辑筛：

| USP 候选 | 防御性 | 备注 |
|---|---|---|
| **U-1 证据链可追溯到 source + url + 时间** | **强** | 大模型做不到（来源不明）；盘口站做不到（不展示推理） |
| **U-2 缺数据时显式说"信息不足"，不编造** | **强** | 反直觉但是核心壁垒；多数产品在产品压力下都会编造 |
| **U-3 OSINT 方法论 + 因子注册表** | 中 | 工程门槛中等，但跨足球+ OSINT 跨界，少有人做 |
| **U-4 不投注语言** | 中 | 容易复制，但能吸引特定用户群（厌恶投注文化的研判型球迷） |
| **U-5 可继续问（追问 chips + 自由文本）** | 弱 | LLM 产品都能做，差异不大 |
| **U-6 微信小程序 + Web 跨端** | 弱（v1.5） | 国内中文产品标配 |

**核心 USP（v1 锚定）**：U-1 + U-2，即"**带证据链的研判，缺数据时不编**"。

## 6. 主张风险

| ID | 风险 | 类型 | 缓解 |
|---|---|---|---|
| RISK-1 | U1（懂球研判型）市场容量太小，撑不起付费 | 市场 | v1 用付费码控成本，先 50-100 真实用户验证；不 burn 流量 |
| RISK-2 | "证据可追溯"实际效果不如 LLM 编故事流畅，用户体感差 | 体验 | 文案设计 + 证据强度可视化；v1 上线后做 5-8 人对比测试 |
| RISK-3 | "信息不足"显示太频繁，用户感觉产品"啥也不是" | 体验 | 阈值调优；提供"哪些数据缺了"的解释，让用户感到产品诚实而非无能 |
| RISK-4 | 公开数据源（Win007 等）反爬升级，导致大部分场次"信息不足" | 数据 | 多源（已配 5 个 host）；v2 考虑接付费数据 |
| RISK-5 | LLM 成本上升 / DeepSeek 限流 | 供应商 | 限流降级到模板路径；备选 ollama 本地模型 |
| RISK-6 | 投注用户硬来，绕开免责声明使用产品做投注，触发监管 | 合规 | 用户协议 + 文案审计 + 不接入赔率显示；不能 100% 防御，但能证明产品没主动诱导 |
| RISK-7 | 微信小程序提审被拒（涉及"足球预测"被关键词识别为博彩） | 平台 | v1.5 提审前文案 sweep；类目选"工具"或"教育" |
| RISK-8 | 单人开发响应慢，用户流失 | 运营 | 反馈 SLA 7 天写明；issue tracker 公开 |

## 7. 与现有解决方案的对比

| 类别 | 代表 | 强项 | 痛点 P 覆盖 | 与世界球花的差异 |
|---|---|---|---|---|
| 赛果预测站 | 球探、捷报、SofaScore Tip | 数据深、用户基数大 | P4 部分 | 我们：带证据链 + 不强推盘口 |
| 论坛/解说 | 虎扑、懂球帝、雪球（足球节点） | 人气、互动 | P5 部分（社交） | 我们：结构化、个人化、无广告 |
| 数据站 | FBref、Transfermarkt | 数据全 | 低（用户要自己组装） | 我们：自动结论化 |
| 通用 LLM | ChatGPT, Claude, DeepSeek | 灵活、能对话 | P5（部分）、J3 | 我们：来源可追溯、不编造 |
| 投注 App | 各类盘口/竞猜 | 直接 | 不解决 P1/P2/P7 | 我们：明确不做投注 |

| 阶段 2 用户访谈关键问题 | "你能在 1 分钟内做出研判吗"、"看到'信息不足'你会失望还是放心"、"你愿意为带证据链付费吗" |

## 9. 未解决问题

- "证据强/弱/不足"的判定阈值由谁定？（建议：因子置信度 ≥ 0.5 = 强，0.25-0.5 = 弱，< 0.25 = 不足；阶段 2 用户访谈时让用户校验）
- v1 是否做"赛后回看"？G4/J4 期望但工程量不小。建议：v1 仅保存提问历史；自动赛后对照放 v2。
- 邀请码可以"无限发放"还是"按月配额"？影响冷启动节奏。
