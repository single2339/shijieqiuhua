# 世界球花 — 需求挖掘计划

## 0. 上下文

进阶段 2 时，已有的产物分两类：

1. **可信度高（基于现有材料）**：86 条草稿需求（RQ-A 到 RQ-G）。
2. **可信度低（基于假设）**：11 个 Open Questions（Q12-Q22），加上阶段 1 的 6 个低强度假设（VPA-A1 到 ASM-1）。

需求挖掘的目的不是"再列一遍需求"，而是**针对低可信度的部分设计有效的取证手段**。86 条草稿 ≠ 86 条经过用户验证的需求。

## 1. 挖掘目标与范围

### 1.1 三个挖掘目标

| 目标 | 优先级 | 失败成本 |
|---|---|---|
| **G1：验证 USP 假设是否成立** — 用户是否真的把"证据链可追溯""不编造倾向"当价值 | P0 | 整个 PRD 方向错位 |
| **G2：填充 11 个 Open Questions（Q12-Q22）的具体取值** | P1 | v1 实施时反复改动 |
| **G3：发现遗漏的 Job-to-be-Done 与隐性约束** | P2 | v1 上线后用户流失 |

### 1.2 范围

| 在范围内 | 范围外 |
|---|---|
| U1 核心用户（懂球研判型）访谈 | U3 投注用户（明确不服务，不取证） |
| U4 邀请发起人意愿调研（已付费阶段） | U2 大赛偶发用户（v1 不优化） |
| 现有 5 名同领域开发者技术评审（如有） | F1-F3 KOL/数据合作方/投资人（v1 后期再做） |
| 微信小程序提审规则前置阅读（P1） | 微信支付商户号申请流程（v1.5 才做） |

### 1.3 时间线

阶段 2 内需求挖掘的总预算：**5 个工作日**。
- D1：制定计划（本文档） + 招募 5-8 人
- D2-D3：5 场 1on1 访谈（每场 60 min）
- D4：观察研究 + 微信平台规则阅读
- D5：findings 汇总，输出 `06-elicitation-findings.md`

## 2. 技术选型与理由

| 技术 | 是否使用 | 主要回答的目标 | 理由 |
|---|---|---|---|
| **半结构化 1on1 访谈** | ✅ 主力 | G1, G2-部分, G3 | 早期产品最重要的是质性洞察，5 人足以覆盖 80% 的关键议题（行业经验） |
| **观察研究**（让 5 人在你旁边/视频中实操现有产品 ChatGPT/球探/SofaScore，并描述决策过程） | ✅ 辅助 | G3, G1 | 用户说的≠用户做的；观察能抓出隐性 Job |
| **轻量原型对比测试**（拿 spec 设计稿 + 当前 MVP App.tsx 给用户看） | ✅ 辅助 | G2-部分（Q13/Q16/Q17/Q19） | 比纯文字访谈更有效让用户校验 UI 决策 |
| **问卷** | ❌ 不用 | — | 5-8 人样本不够做问卷统计；问卷适合 v1.5 之后 |
| **大型 workshop** | ❌ 不用 | — | 单人项目 + 用户分散，组织成本高于收益 |
| **文档审阅**（spec / 微信小程序文档 / OSINT 主项目） | ✅ 已部分完成 | G2-部分（合规相关） | 阶段 1 已读 spec；阶段 2 补微信平台规则 |

## 3. 访谈计划

### 3.1 受访者招募

**目标**：5-8 名 U1 用户。

**画像**：
- 看球 5 年以上
- 每周看比赛 ≥ 2 场
- 自己做过研判（不是只看胜负）
- 反例：完全不看数据的、纯投注玩家、只看本国联赛偶尔关心一下的

**渠道（按优先级）**：
1. 你自己的足球同好（直接邀请）
2. 现有产品种子用户邀请名单（如有）
3. 通过虎扑/懂球帝/同事二度关系扩散

**关键决策（Q11，阶段 1 待补）**：必须在 D1 结束时定 5-8 人具体名单。

**激励**：
- 1 个月内的免费付费码（v1 上线后兑换）
- 不发现金（避免讨好性回答）

### 3.2 访谈结构（每场 60 min）

| 段 | 时长 | 目标 | 形式 |
|---|---|---|---|
| 0. 暖场 + 知情同意 | 5 min | 录音/记录授权 | 自由对话 |
| 1. 现状映射 | 15 min | 抓 J1-J7 真实优先级 + 现有解决方案 | 问"上一次你研判一场比赛"流程 |
| 2. 痛点深挖 | 15 min | 验证 P1-P8 + 发现新 Pain | 探询"那个时候你最烦的是什么" |
| 3. 价值假设测试 | 15 min | G1（USP）+ Q3（信息不足） + Q13（可信度展示） | 给场景对比 + 给原型 |
| 4. 商业化意愿 | 5 min | Q1 验证 + 邀请意愿（U4） | 直接问 |
| 5. 收尾 + 让用户提问 | 5 min | 暴露盲区 | 让用户问你 |

### 3.3 问题银行

按 5W2H 风格组织。每条标注**回答的目标**和**期望的证据类型**。

#### 段 1. 现状映射

| ID | 问题 | 目标 | 期望证据 |
|---|---|---|---|
| Q1.1 | 上一次你认真研判一场比赛是什么时候？讲讲那一次的过程。 | J1-J4 | 行为序列 |
| Q1.2 | 你打开了哪些 App / 网站 / 工具？分别看了什么信息？ | 替代品分析 | 工具清单 |
| Q1.3 | 在做最终判断时，哪个信息让你最有信心？哪个让你最犹豫？ | J2 + Pain | 决策权重 |
| Q1.4 | 你看完之后，会跟谁讨论吗？会怎么讲？ | J5, J7 | 社交模式 |
| Q1.5 | 那场比赛结果如何？你赛后会回看自己赛前的判断吗？ | J4 | 回看习惯 |

#### 段 2. 痛点深挖（probe-question-generator 风格）

| ID | 问题 | 目标 | 期望证据 |
|---|---|---|---|
| Q2.1 | 刚才你提到 [X 工具]，最让你不爽的是什么？ | P1-P8 验证 | 具体抱怨 |
| Q2.2 | 如果有一个工具能帮你解决 [Y 痛点]，你最希望它怎么呈现结果？ | G1, G2 | 期望产品形态 |
| Q2.3 | 你有没有过"我心里有疑问但找不到地方问"的时候？讲一下。 | P5 | 隐性 Job |
| Q2.4 | 你看研判文章/视频时，最烦广告/带货吗？还是别的？ | P3, P7 | 体验偏好 |
| Q2.5 | 你用过 ChatGPT/Claude/DeepSeek 问比赛吗？效果怎样？ | P2 + ASM-VPA-A2 | LLM 替代品现状 |

#### 段 3. 价值假设测试（核心）

| ID | 问题 / 操作 | 目标 | 期望证据 |
|---|---|---|---|
| Q3.1 | （场景对比）我给你看两份赛前简报：A 只给"主队倾向 60%"，B 给"主队倾向 60% + 5 条证据 + 缺什么没说"。你会更信哪一份？为什么？ | G1（USP U-1） | 偏好选择 + 理由 |
| Q3.2 | （场景对比）现在改成另一个对比：C 给一个倾向但你看不出推理；D 不给倾向，写"信息不足，缺首发数据"。你会更想用哪个？ | G2（USP U-2） + Q3 | 偏好 |
| Q3.3 | （现 MVP 截图 + spec 设计稿）这是当前产品和设计稿。哪个更接近你期望？为什么？ | Q13 / Q16 / Q19 | 设计偏好 |
| Q3.4 | "可信度 L3"和"可信度 60%"，哪种表述对你更有用？为什么？ | Q13 | 表述偏好 |
| Q3.5 | "信息不足"应该出现的场景：(a) 完全没数据 (b) 数据冲突 (c) 数据少但有方向。哪种你会接受？ | Q14 阈值 | 阈值锚点 |

#### 段 4. 商业化意愿

| ID | 问题 | 目标 | 期望证据 |
|---|---|---|---|
| Q4.1 | 这种带证据链的产品，你愿意付费吗？大概什么价位？ | Q1 + Q8 | 价格意愿区间 |
| Q4.2 | 必须用邀请码才能注册，你能接受吗？ | ASM-VPA-A4 | 门槛接受度 |
| Q4.3 | 如果你是已付费用户，你会主动邀请几个朋友？ | U4 邀请意愿 | 邀请潜力 |
| Q4.4 | 付费形式：(a) 月度订阅 (b) 一次性付费码 (c) 单场付费。你倾向哪种？ | Q1 + Q8 | 付费形态偏好 |

#### 段 5. 收尾

| ID | 问题 | 目标 |
|---|---|---|
| Q5.1 | 你还想问我什么？ | 暴露我的盲区 |
| Q5.2 | 这个产品如果做出来，你会推荐给谁？为什么？ | 找下一批受访者 |

### 3.4 偏差控制

| 偏差风险 | 缓解 |
|---|---|
| **讨好性回答**：用户夸产品 | 多问"哪里不好"，少问"是不是好" |
| **想象式回答**：用户说"我会用"但其实不会 | 多问"上一次你做了什么"，少问"你愿不愿意" |
| **引导性问题**：访谈者带预设 | Q3.1/Q3.2 用对照而非选项；不说"我们的产品" |
| **小样本偏倚**：5-8 人 ≠ 全体用户 | findings 报告中显式标注样本量；有反对意见时单独记录 |

## 4. 观察研究计划

### 4.1 形式

让 3 名访谈者额外做一次 30 min 观察任务（自愿；可在访谈日同时安排）：

1. 给一场具体比赛（用户没研判过的）。
2. 让用户在自己设备上做 5 分钟研判，**说出每一步在做什么、看什么、为什么看这个**（think-aloud）。
3. 记录：打开了哪些工具、停留时长、第一个查的信息是什么、最后做出判断的依据。

### 4.2 关注点

- J1（赛前判断时间）实际花了多久？
- 第一个查的信息是什么？（间接验证最重要的因子）
- 哪几步是在工具间切换？（间接验证 P6 移动端体验）
- 用户什么时候放弃 / 决定？

## 5. 原型对比测试

### 5.1 准备材料

**A 版**：当前 MVP（`frontend/src/App.tsx` 单页 + `MatchQuestionCard`）。
**B 版**：spec frontend-design 设计稿（已有 `2026-06-11-shijieqiuhua-frontend-design.md` 但无视觉稿，需补 wireframe）。

行动项：D1-D2 内补 B 版 wireframe（用 Figma 或 Excalidraw，≤ 3 页：列表页 / 比赛卡 / Ask 面板）。

### 5.2 测试流程

每位受访者 5 min：
1. 给 A 版让用户用 1 分钟。
2. 给 B 版让用户看 1 分钟（不能交互，只看图）。
3. 问：哪个让你更想用？哪些细节最能/最不能打动你？

## 8. 风险与降级路径

| 风险 | 缓解 |
|---|---|
| 招不齐 5 人 | 至少 3 人也能覆盖核心假设；样本量不足时 findings 中显式说明 |
| 受访者集中在某类（如全是工程背景） | 招募时主动控制画像多样性 |
| 访谈中暴露 USP 不成立 | 立即停止往下做 PRD，回到阶段 1 重新框定 |
| 受访者全部接受邀请门槛 | 重新审视：是不是只能招到本来就接受的人？需要补访"门槛敏感者" |
| 时间预算超支 | 5 人减到 3 人是可接受的；技术选型保留观察+原型作为冗余 |

## 10. 用户暂时无法做用户访谈的降级路径

> 实际情况：你是单人开发者，可能没法立刻招到 5-8 人。本节给一个**降级版的需求挖掘**。

### 降级版输入
1. 你自己作为"代理用户"做一遍 think-aloud。
2. 阶段 1 已有的所有材料。
3. 同类产品（球探、SofaScore、ChatGPT for football）的公开评论。
4. 你日常和球友的非结构化对话回忆。

### 降级版产出
`06-elicitation-findings.md` 仍然交付，但显式标记：
- 来源：自我代理 + 公开评论
- 假设强度全部降为"低"
- 阶段 3 的缺口审计要把"用户访谈未做"列为最大缺口
- v1 上线后必须在前 4 周内补 5 人访谈

### 适用条件

如果你确认**短期内（1 周内）招不到 5 人**，按降级版走；否则尽量做完整版。
