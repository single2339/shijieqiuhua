# OSINT Network 白皮书

## 1. 项目定位

OSINT Network 是一个面向情报分析人员的开源情报（OSINT）采集、处理、分析与可视化平台。系统从公开数据源（RSS、Reddit、HackerNews、Telegram、GitHub）持续采集多语言信息，经过翻译、摘要、分类、地理定位、贝叶斯可信度评估等处理链路，最终通过交互式地图和仪表盘呈现实时情报态势。

**核心能力：**

- **多源采集** — 覆盖 16 种以上数据源类型，支持 RSSHub 扩展中文源
- **12 情报图层** — 自然生态、经济产业、金融、政治外交、军事、民航交通、科技、社会民生、能源资源、农业食品、公共卫生、网络空间
- **4 级可信度体系** — L1（确认）→ L4（推测），基于独立来源数量与交叉验证
- **贝叶斯证据引擎** — 先验概率 × 似然比 × 证据依赖折扣 → 后验概率，可审计可追溯
- **结构化研判输出** — 关键判断、确认事实、替代解释、待核查项，事实/推断分离
- **交互式态势感知** — 地图可视化、时间线、实体图谱、交叉验证矩阵、风险热力图、覆盖缺口分析

- **无数据库依赖** — 所有数据经 JSON 文件流转，SQLite 仅用于加速检索

## 3. 数据流设计

### 3.1 采集流水线

```
RSS/Reddit/HN/Telegram/GitHub → 翻译 → 摘要 → LLM分类 → 地点提取 → 写入Bronze JSON
```

采集由 Agent 编排系统驱动，支持：
- **定时采集** — `OrchestratorAgent` 管理采集循环
- **手动触发** — `POST /api/collect?hours=48`
- **WebSocket 实时推送** — `/ws/collection` 频道广播采集进度

### 3.2 索引与服务

```
Bronze JSON → SQLite Indexer (增量更新) → Dashboard 缓存 (两阶段) → API 响应
```

**两阶段缓存架构：**
1. **Master List Cache**（TTL 300s）— 缓存按日期范围扫描的全量 item 列表（最昂贵操作）
2. **Page Variant Cache**（TTL 300s）— 缓存按分页参数构建的 `DashboardData`（不同 page/page_size）

### 3.3 内容合并引擎

每日 03:00 UTC 自动运行，三键 Union-Find 去重：

1. **相同 source_url** — 两篇文档引用同一来源 URL
2. **相同 content_sha256** — 内容完全一致
3. **相同归一化标题** — 标点归一化后标题匹配

合并结果写入 `_merge_index.json`，API 读取后展示多来源合并的 `IntelItem.sources[]` 列表。

## 5. 可信度体系

### 5.1 五级置信度

| 等级 | 标签 | 判定标准 |
|------|------|---------|
| L1 | 确认 | ≥3 个独立支持来源且假设后验 ≥0.60 |
| L2 | 高可信 | ≥2 个独立支持/反对来源且假设后验 ≥0.50 |
| L3 | 中可信 | ≥1 个独立来源且假设后验 ≥0.45 |
| L4 | 推测 | 未达到上述独立来源与后验门槛 |
| L5 | 无效 | 假设被反驳或后验 ≤0.30 |

等级由去重后的独立来源数量和假设后验共同决定。单一来源即使产生较高后验也最多为 L3；
转载副本不增加独立来源数量。

### 5.2 假设级贝叶斯证据引擎

超级分析只对一个明确、可证伪的假设计算后验概率。文档长度、数字密度和来源声誉仅形成
`quality_score`，用于同等相关性候选的排序，不作为主张真值概率。

```
先验赔率 = 0.5 / (1 - 0.5)
后验赔率 = 先验赔率 × Π(固定似然比_i)
后验概率 = 后验赔率 / (1 + 后验赔率)
```

LLM 只标注每条已采集证据与假设的关系和强度：

- `support` / `contradict` / `neutral`
- `weak` / `moderate` / `strong`
- `rationale` — 关系判定理由

Python 使用固定 LR 映射集中更新一次；`neutral` 的 LR 恒为 1。同一通讯社、转载链或同一
原始出处归为同一个依赖组，每组只更新一次，重复证据的 LR 固定为 1，避免转载数量虚高后验与 L1–L5 等级。
网络搜索摘要属于未验证线索，固定为 `neutral/weak`，不会改变后验。

超级分析响应包含假设、先验、逐证据 LR 与后验轨迹、最终后验、判断、独立证据源数量和
L1–L5 等级，供前端展示和导出审计。通用文档质量接口不返回后验、判断或置信等级。

## 7. 部署架构

```
┌──────────────────────────────────────────────────────────┐
│                   Ubuntu 24.04 Server                     │
│                                                           │
│  ┌─────────────────┐  ┌──────────────────────────────┐   │
│  │   Nginx :80      │  │   RSSHub Docker :1200        │   │
│  │   / → 静态文件    │  │   微博/CLS/早报 RSS 源       │   │
│  │   /api/ → :8000  │  └──────────────────────────────┘   │
│  └────────┬─────────┘                                     │
│           │                                               │
│  ┌────────┴─────────────────────────────────────────┐    │
│  │   osint-network.service (systemd)                 │    │
│  │   uvicorn backend.main:app --port 8000            │    │
│  │                                                    │    │
│  │   OSINT_ROLE=worker → 后台采集 + 合并 + 索引      │    │
│  │   OSINT_ROLE=api    → HTTP 服务 + 缓存预热        │    │
│  │   OSINT_ROLE=all    → 单进程模式（开发用）         │    │
│  └────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────┘
```

**双进程分离部署：**
- `OSINT_ROLE=api` — 处理 HTTP 请求，预热 dashboard 缓存
- `OSINT_ROLE=worker` — 运行采集循环、合并引擎、索引更新
- 前端静态文件由 Nginx 直接提供，构建产物 `frontend/dist/` 通过 rsync 同步

**环境变量关键配置：**
- `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` — DeepSeek API
- `ANALYSIS_REALTIME_ITEM_LIMIT=3000` — 分析端点样本上限
- `STATS_DEFAULT_DAYS=14` — 统计默认窗口
- `CORS_ORIGINS` — 允许的前端域名

## 8. 合规声明

本系统仅采集**公开可访问**的信息源（RSS 订阅、公开 API、公开网页），不进行任何形式的：
- 未授权访问或渗透测试
- 个人隐私数据采集
- 受版权保护内容的批量下载
- 规避访问控制或 robots.txt 限制

所有采集内容均保留原始来源链接，支持溯源验证。系统设计遵循 OSINT 行业最佳实践，事实与推断分离，置信度可审计。
