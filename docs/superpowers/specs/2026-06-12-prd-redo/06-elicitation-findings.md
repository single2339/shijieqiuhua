# 世界球花 — 需求挖掘 Findings（降级版）

## ⚠️ 重要前置声明

本报告**未做真实用户访谈**。所有发现来源：

1. **自我代理**（产品负责人 = 用户 U1 画像之一）
2. **公开评论调研**（虎扑/懂球帝/微博中关于"足球预测""赛前研判"的公开讨论）
3. **同类产品体验**（球探、捷报、SofaScore、FBref、ChatGPT for football）
4. **行业经验推断**

**强度全部为"低"**。每条发现都标 `[低]` 提醒。v1 上线后**前 4 周内必须补 5 人访谈**，否则 PRD v1 的核心假设没有真实证据。

## 2. 关键发现汇总（按目标对照阶段 1 假设）

### G1：USP 假设验证

| 假设 | 验证结果 | 证据强度 | 来源 |
|---|---|---|---|
| ASM-VPA-A1 目标用户是 U1 懂球研判型 | **部分支持** [低]；公开评论显示存在该群体（虎扑、懂球帝中"赛前分析"贴常有 50+ 评论），但占总用户比例未知 | 公开评论 | 论坛活跃度 |
| ASM-VPA-A2 用户已用 LLM 问比赛且不满意 | **部分支持** [低]；ChatGPT/DeepSeek 在足球分析上的常见抱怨：信息过期、生造数据、来源不明 | 自我代理 + 推断 | think-aloud + 行业常识 |
| ASM-VPA-A3 用户愿意为带证据链付费 < ¥30/月 | **未验证** [低]；现有付费产品（虎扑会员、懂球帝会员）月费 ¥10-20，足球数据站无主流付费产品 | 价格调研 | 同类产品 |
| ASM-VPA-A4 用户接受"研判 ≠ 胜负预测" | **部分支持** [低]；自我代理认可；但公开评论中大量"求今晚预测"型用户混在研判型中，边界模糊 | 公开评论 | — |
| ASM-VPA-A5 "足球研判"是真实细分品类 | **部分支持** [低]；现有产品中"赛果预测站"占主流，"研判型"被论坛取代而非有专门工具 | 同类产品 | 市场扫读 |
| **U-1 证据链可追溯（USP 核心）** | **支持但需要看怎么呈现** [低]；自我代理认为关键，但实施呈现不当（一堆 url）反而制造噪音 | 自我代理 | think-aloud |
| **U-2 不编造倾向（USP 核心）** | **支持但有体感风险** [低]；自我代理认为有价值；但"信息不足"频率太高会让用户觉得"啥也不是"（与 03-VPC RISK-3 一致） | 自我代理 | think-aloud |

**结论**：USP 方向**不被反驳**，但强度等待真实用户验证。**不需要回阶段 1**。

### G2：Open Questions 取证

| QID | 问题 | 自我代理 + 调研结论 | 强度 |
|---|---|---|---|
| Q11 | 5-8 名核心用户名单 | 未解决；v1 上线前必须列 | — |
| Q12 | 短信/邮件验证码服务商 | **建议**：v1 仅邮箱（Resend 或 SMTP），短信延后到 v1.5；阿里云短信备选 | 推断 [低] |
| Q13 | 可信度展示形式：% / L1-L4 / 双形式 | **建议**：双形式 — L 等级为主（更易理解），% 为辅（hover 展示精确值） | 自我代理 [低] |
| Q14 | "信息不足"阈值 | **建议**：因子启用数 ≤ 1 或所有启用因子置信度均值 < 0.30 → "信息不足"；阶段 4 上线后用真实数据校准 | 自我代理 [低] |
| Q15 | 用户问答历史持久化方式 | **建议**：v1 用 SQLite（已有 indexer.py）+ bronze JSON 双写；问答记录单独建表 | 工程推断 [低] |
| Q16 | 证据 URL 显示方式 | **建议**：默认显示 source 标签 + 小图标，hover/点击展开 url；移动端展开为半屏抽屉 | 自我代理 [低] |
| Q17 | 未付费用户证据数量预览 | **建议**：显示"X 条强证据"作为数字，不显示标题；制造"看完整内容需要付费"的引力但不展示具体内容 | 自我代理 [低] |
| Q18 | bronze 落盘文件子集 | **建议**：v1 必须落 request.json / status.json / report.md / provenance.json；其他可选 | 工程推断 |
| Q19 | Web 移动端响应式优先级 | **建议**：v1 必做基础响应式（< 768px 单栏布局），但不做"移动端深度优化"；v1.5 小程序补齐 | 工程推断 |
| Q20 | "推荐追问"算法 | **建议**：v1 用静态推荐：按当前比赛 profile 给固定 3 条；v2 接入历史和因子缺失 | 工程推断 |
| Q21 | 用户协议/隐私政策来源 | **建议**：基于通用模板（GitHub 上 termly/privacy-policy-template）+ 自改；上线前找朋友帮看一遍 | 实操推断 |
| Q22 | 邀请码/付费码默认有效期 | **建议**：邀请码 30 天、付费码 90 天（兑换有效期）；兑换后权益默认 30 天 | 自我代理 [低] |

**8/11 个 Q 有"低强度建议取值"**；Q11 必须 v1 启动前补；Q12 等到 v1.5 再决。

### G3：新发现的 Job / Pain（隐性需求）

下面的 RQ-* 是从自我代理 think-aloud + 公开评论调研中**新发现**的、原 86 条草稿没有的：

| 新 RQ ID | 描述 | 强度 | 建议归入类 |
|---|---|---|---|
| RQ-NEW-1 | **用户希望在比赛卡上看到"已知缺什么数据"**（不只是"信息不足"，而是具体到"缺首发""缺天气"），便于用户决定是否手动补 URL | [低] 自我代理 | C 证据系统 |
| RQ-NEW-2 | **用户希望快速对比 2-3 场比赛**（同一晚多场赛事时，想看哪场最值得看） | [低] 自我代理 | E Web UI（v2） |
| RQ-NEW-3 | **用户对"AI 怎么这样判断"的解释敏感**：希望 LLM 自由提问回答中能引用证据 ID（如 [ev_003]），不是泛泛而谈 | [低] 自我代理 | B 核心研判 |
| RQ-NEW-4 | **用户对"赛后回看"有需求**：赛后想看自己的赛前判断对不对、产品的研判对不对 | [低] 自我代理 + 公开 | B 核心研判（v2） |
| RQ-NEW-5 | **用户在中国大陆访问海外数据源时网络不稳**：Win007/SofaScore 直连可能慢/失败 | [低] 工程实测 | F 非功能 |
| RQ-NEW-6 | **用户想要"分享给球友看"但不想透露付费身份**：分享卡片不应含个人信息 | [低] 公开评论 | E + G 业务规则 |
| RQ-NEW-7 | **用户对"产品边界"敏感**：不喜欢"我们能预测一切"的口气；产品要表现出"知道自己不知道什么" | [低] 公开评论（对 LLM 编造的反感） | E 文案 |
| RQ-NEW-8 | **用户不希望看到隔夜的"过期主判断"**：开赛前 6 小时内的判断比 24 小时前的更有价值 | [低] 自我代理 | D 后端（缓存策略） |

### G3 续：用户更不在意的（去优化项）

| 推断 | 理由 |
|---|---|
| 历史 H2H 战绩用户其实不太关心（青年赛/友谊赛尤其） | 与 spec 一致；与原 RQ-D-6 一致 |

| 复杂账户体系（多角色、团队）零需求 | 与决策一致 |

## 3. 同类产品对比扫读

| 产品 | 强项 | 缺点 | 启示 |
|---|---|---|---|
| **球探/捷报** | 数据全、用户基数大 | 大量赔率盘口、广告多、UI 老 | 不学这种"信息密集型"展示 |
| **SofaScore** | 现代 UI、数据时效好 | 不结论化、英文为主 | 学其卡片化展示 |
| **FBref** | 数据深 | 几乎只是数据库，无叙事 | 不直接对标 |
| **ChatGPT/DeepSeek** | 自由对话 | 数据陈旧、来源不明、爱编故事 | 直接竞品；强化"来源可追溯"差异 |
| **懂球帝** | 社区强、内容编辑 | 内容靠人写、不结构化 | 学其文案语感（懂球味儿） |
| **虎扑足球区** | UGC、讨论度高 | 不工具化、看完没法存 | 启示：报告页要可保存、可分享 |

## 6. 冲突与未触及

### 6.1 内部冲突（自我代理与公开评论间）

| 冲突 | 双方 | 处理 |
|---|---|---|
| 自我代理认为"信息不足"是诚实美德；公开评论中"找不到数据"是负面体验 | 自我代理 vs 公开抱怨 | 不平滑：v1 锁"信息不足"显示，但要强化"缺什么"细节让用户感到产品诚实 |
| 自我代理重视"证据链"；公开评论用户主要抱怨"分析不准" | 自我代理 vs 一般用户 | v1 接受 USP 是"懂球研判型"用户的偏好；不取悦"求准"型用户 |

### 6.2 未触及的盲区

| 盲区 | 原因 | 计划 |
|---|---|---|
| 真实用户的"研判耗时"分布 | 没有用户行为数据 | v1 上线后埋点 |
| 邀请码门槛的真实拦截力 | 需要冷启动后才能测 | v1 上线后转化漏斗 |
| 付费意愿的真实价格曲线 | 自我代理样本 = 1 | v1 用付费码免费发，用兑换率倒推 |
| U2 边缘用户被门槛拒之门外的反应 | 没访问到该群体 | 接受这个盲区；v1 不优化该群体 |
| KOL 和 V 类用户对产品的看法 | 未触及 | v1 上线后定向邀请 |

## 8. 强度声明（再次强调）

本文档所有发现的强度等级：

```
高强度  (实际证据支撑)：  0 条
中强度  (多源印证)：      3 条
低强度  (自我代理/单一源)：~ 40 条
未验证  (假设)：          剩余
```

阶段 3 必须把"低强度"和"未验证"作为缺口处理；**不能在阶段 3-5 把它们当成真实需求**来排优先级。
