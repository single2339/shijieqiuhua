# 合法边界、审计字段与数据分级策略

本文档在**任何渠道扩展或采集任务上线之前**必须评审并固化；变更需版本化记录。

## 1. 合法与合规边界

### 1.1 采集范围原则

| 原则 | 说明 |
|------|------|
| 公开可得 | 仅处理法律与平台规则允许公开访问或授权访问的数据 |
| 授权优先 | API/合作数据优先于网页抓取；抓取须符合 robots.txt 与站点 ToS |
| 区域法规 | 涉及欧盟等地区个人数据时，遵循 GDPR 等关于处理目的、法律依据与留存最小化的要求 |
| 禁止默认项 | 不将绕过鉴权、破解、违反 ToS 的采集作为系统默认路径 |

### 1.2 渠道准入闸门

每个新数据源上线前需完成：**数据源清单**、**法律依据/合同**、**留存周期**、**PII 处理策略** 四项评审，由合规负责人签字（或等效流程）。

## 2. 审计字段（全链路必填）

所有进入原始证据层及下游的对象，在元数据中应能回答：**谁、何时、从何渠道、用何版本、内容指纹为何**。

| 字段 | 说明 | 示例 |
|------|------|------|
| `source_system` | 逻辑来源（站点/API/适配器名） | `reuters_public_rss` |
| `source_url` / `api_endpoint` | 可复核的定位符 | HTTPS URL 或规范化的 API 路径 |
| `captured_at` | UTC 采集时间 | ISO-8601 |
| `collector_id` | 采集器/作业标识 | `web-adapter@v1.2.0` |
| `collector_version` | 语义化版本 | `1.2.0` |
| `job_id` | 上游任务 ID | UUID |
| `tenant_id` | 多租户隔离 | UUID 或固定 `default` |
| `content_sha256` | 原始内容哈希 | 十六进制小写 |
| `transport_hash` | 可选：传输层完整性 | 若经队列则对 payload 再哈希 |

下游标准证据层和情报产品层**不得丢弃**上述字段的引用关系；可冗余存储 `provenance_chain[]` 指向父记录。

## 3. 数据分级（Data Classification）

用于访问控制、脱敏策略与导出审批。

| 级别 | 代号 | 描述 | 存储与访问 |
|------|------|------|------------|
| L0 | `PUBLIC_AGG` | 完全聚合、无个人指向的统计 | 默认可读 |
| L1 | `PUBLIC_DOC` | 公开网页/公告等无敏感 PII | 项目内标准访问 |
| L2 | `SENSITIVE_METADATA` | 含间接身份线索或商业敏感 | 角色限制 + 审计日志 |
| L3 | `PII` | 可直接或间接识别个人 | 最小化字段、加密、留存 TTL、导出审批 |
| L4 | `RESTRICTED` | 合同/法律限制或高敏研究 | 独立租户或物理隔离、双人控制 |

**默认策略**：能降级的字段在标准证据层即做脱敏或哈希化；L3 仅在业务必需时保留，并配置自动过期任务。

## 4. PII 与敏感字段处理

- **识别**：在原始证据层到标准证据层的管道中运行可配置的个人信息检测（规则 + 可选模型），打标 `pii_flags[]`。
- **最小化**：情报产品层分析视图默认排除原文个人信息，仅保留 `entity_id` 与聚合指标。
- **跨境**：数据区域与备份区域需在架构图中标明；跨区域复制需单独评估。

## 5. 留存与删除

- 每类数据源配置 `retention_days`；到期原始证据可归档或删除，标准证据层和情报产品层若依赖派生需采用级联策略或匿名化保留。
- 支持按 `source_system` + 时间范围执行**合规删除**（含对象存储与索引）。

## 6. 威胁与滥用面（摘要）

| 威胁 | 缓解 |
|------|------|
| 内部滥用高敏数据 | RBAC、审计查询、异常访问告警 |
| 采集器被篡改注入假数据 | `content_sha256`、签名镜像、CI 对采集器版本的构建溯源 |
| 下游模型幻觉当事实 | 可验证主张级输出必须带来源 `doc_id`；低置信度进入人工队列 |

本文档版本：`1.0.0`，与仓库 `schemas/` 中审计扩展字段同步演进。
